How to Stop Prompt Injection From Draining Your AI Agent's Wallet

MandateGuard · 2026 · Landing

Prompt injection doesn't steal your API keys — it steals one decision: the decision to authorize a payment. An attacker embeds "refund this customer to this address" in an email, a webpage, a tool result. The agent reads it, and if the authorization check is part of the same probabilistic context, the money moves. This guide is the practical answer to that attack class.

Why the authorization is the target

Your agent can't be made immune to reading untrusted content. What you can change is what happens after it reads it. If the final "approve this transfer" step is:

  • Deterministic — a pure function of (actor, tool, amount, destination, policy) with no model sampling
  • Outside the prompt — the injected text has no path into the decision inputs
  • Scoped — the agent can only spend within an issuer-signed mandate

...then the injection has nothing to push against. The best prompt in the world cannot exceed the allowlist.

Layer 1: destination allowlists

The cheapest win. The agent can only send to addresses/accounts that were pre-approved:

policy = Policy(
    scopes={"wallet-agent": Scope(
        tools=("pay",),
        destinations=("0xGOOD", "0xTRUSTED-VENDOR"),
        max_amount=1000, currency="usd",
    )},
    allowlist=("0xGOOD", "0xTRUSTED-VENDOR"),
)
engine = PolicyEngine(policy)
engine.authorize(Intent(tool="pay", destination="0xATTACKER", amount=50,
                        actor="wallet-agent"))
# -> DENIED (destination not allowed)

No matter what the attacker's email says, the destination check happens in code, not in context.

Layer 2: per-call and per-window budgets

Even for allowed destinations, cap the blast radius. Per-call max stops a single "refund everything" prompt; per-window limits stop a burst of small transfers that sum to a drain:

Scope(tools=("pay",), destinations=("0xGOOD",), max_amount=1000,
      currency="usd", max_calls_per_window=5)

Layer 3: signed mandates the agent cannot mint

The agent should not hold the authority to authorize its own payments. Mandates are Ed25519-signed offline, nonce-bound, time-boxed tokens you issue by hand (or via your ops tooling):

from mandateguard import Mandate, MandateSigner, verify_mandate
issuer = MandateSigner()                # private key stays offline
m = Mandate(actor="wallet-agent", max_amount=500, currency="usd",
            tools=("pay",), destinations=("0xGOOD",),
            not_before="2026-01-01T00:00:00+00:00",
            not_after="2099-01-01T00:00:00+00:00",
            nonce="abc", issuer="you")
token = issuer.sign(m)
assert verify_mandate(token)             # tamper-proof

Layer 4: tamper-evident audit

When an incident happens — or an auditor asks — you need to prove what was approved, when, and under which policy. Every decision lands in a SHA-256-chained, append-only ledger; any edit, reorder, or deletion is detected by a linear scan:

ledger.append(decision)
assert ledger.verify()   # True if untouched
